# 2026-05-29 日報｜好理家在知識庫戰情室優化

## 今日完成

- 完成知識庫戰情室第一輪復盤，確認任務本質已從單次文章盤點升級為內容戰情室 workflow。
- 將「新增建議」優化為資料檔驅動架構：新增 `suggestions.json`，前端優先讀取資料檔，再回退到頁面內備援資料。
- 新增內容審稿 Rubric，包含來源可信度、台灣情境具體度、案例治理、Prompt 符合度、可行動下一步。
- 在每則建議卡加入審稿評分欄位，讓「可審稿」「需補證」「可上稿」更容易判斷。
- 保留核准暫存庫、分類存放、JSON 匯出、Markdown 匯出功能。
- 補充 Codex 後續優化草案，作為全域 skill 與 automation 調整前的審核材料。

## 主要發現

- 登入態是知識庫盤點的關鍵。公開 API 與登入後瀏覽器看到的內容差異很大，因此後續盤點應固定加入瀏覽器登入態檢查。
- 新增建議不能只停在題目靈感，必須先有台灣制度、資料、案例或可行動窗口，否則容易變成概念型文章。
- Agent 最有價值的位置不是同時寫草稿，而是分工審稿：一個查資料真實性與案例治理，一個看 prompt 符合度與實用性。
- 審稿台比靜態報告更接近實際工作流程，因為 Kevin 可以點開草稿、核准、退回補證，並依分類暫存。

## 風險與限制

- 目前核准狀態仍使用瀏覽器 `localStorage`，適合 MVP，不適合作為跨裝置唯一正式紀錄。
- `suggestions.json` 可以被週報 automation 更新，但正式自動寫入 repo 前仍需要 Kevin 另行核准。
- 草稿引用的數據、制度與案例在正式上稿前仍需覆核最新公告與查詢日期。

## 建議下一步

- 將 `suggestions.json` 作為週報新增建議的主要輸出格式。
- 觀察 2 至 3 次週報後，再決定是否把這套流程提升為全域 Codex skill。
- 若審稿台確實會多人使用，下一版應接 GitHub PR 或 Google Sheet 來保存核准狀態。
