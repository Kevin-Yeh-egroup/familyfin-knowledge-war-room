# 好理家在可投稿文章生成標準 v3

更新日期：2026-06-17

## 目標

每週產出的內容不是「新增建議」，而是不同主題、可閱讀全文、可複製標題與純文字正文、且生成端持續累積審核成功與審核駁回學習的文章包。

這一版依 Kevin 回饋修正三件事：

- 投稿工作台只顯示純文字正文，不顯示 Markdown、SEO、AIO、Meta、Slug 或 FAQ 欄位。
- 文章若需要表格，表格必須以結構化欄位保存並在工作台顯示為真正表格；不得把 Markdown table、`|` table 或全形 `｜` 文字表當成正文最後輸出。
- 字數門檻以正文計算，扣除標題、標籤、來源、SEO/AIO、FAQ、審核紀錄後仍需超過 2000 字。
- 文章不能只是概念性描述，必須有台灣生活情境、具體壓力、可查核資料與可理解的下一步。
- 「不要概念文」不只是補資料，還必須讓讀者看見數值差異、改善關鍵與符合讀者版本的書寫角度。
- 預設一律生成一般民眾版；社工版只有 Kevin 明確提出時才生成。
- 正文不得混入作者、編輯、agent 或審稿者的建議。所有內部規劃、修稿建議與 gate 自評都只能保留在內部欄位。
- 標題不能讓整批文章看起來像系列模板；除非 Kevin 明確要求系列文章，否則每批標題需混合不同句型與切入角度。
- 標題不能只做到語意正確；若標題像報告摘要、平鋪直述、缺少生活鉤子，或只是把幾個壓力片語排在一起，即使資訊清楚也必須退回重擬。
- 2026-06-09 代理討論後新增：假設性議題需先驗證，文章需同時通過易讀吸引力、家庭財務評估幫助與財務知能轉移檢查。
- 2026-06-10 代理討論後新增：文章不能只描述缺口，必須說清楚可討論的改善計畫、具體施行效果、改善後剩餘缺口，以及打平或合理求助路徑。
- 2026-06-10 來源邊界新增：通過稿作者學習只可使用事件列表中「客戶‑個人」欄位等於目標作者本人的完整文章內容；不得把 FB 短文、社群導流文或只有摘要的貼文當成文章結構樣本。
- 2026-06-11 生成流程新增：三張通過稿結構卡必須轉成每篇文章的 `approvedAuthorStructureUse`。缺少採用紀錄、三種結構未覆蓋、或正文出現學習/審稿語，均不得進入文章工作站。
- 2026-06-15 工作站定位修正：文章工作站只提供文章檢視與複製標題＋正文，不負責提交、核准、退修、駁回或保存本機審核狀態。
- 2026-06-15 生成品質新增：每篇文章必須通過 `articleUsefulnessReview`，確認文章只推動一個家庭財務判斷、先擋掉常見誤判，並留下讀者讀完後可檢查的一個數字、日期、風險或選擇。
- 2026-06-17 退件學習新增：現金流與繳房租焦慮題材不能只保留敘事或表格，必須帶讀者完成結構性財務與現金流盤點。
- 2026-06-17 退件學習新增：資遣、失業給付、補助資格、債務條件等高變異題材，不得用單一或雙個案情境作為主要參考；若條件差異會左右答案，應改成變數盤點、決策清單或工具型內容。
- 2026-06-17 二次 gate 新增：每篇文章必須通過 `financialRiskDecisionReview`，確認文章能協助讀者判斷家庭財務風險、看懂風險造成的家庭財務後果，並選擇符合台灣現況、符合邏輯、不過度牽強的解決方法。
- 2026-06-17 生成細節新增：使用化名情境時必須先通過 `pseudonymFreshnessReview`，不得沿用近期文章包已出現過的化名，避免文章看起來像模板複製或假情境輪替。

## 必過門檻

- 正文扣除所有平台欄位後，必須超過 2000 字。
- 工作站預覽與複製輸出必須是純文字。
- 不得輸出 Markdown 標記作為投稿正文。
- 需要表格時，工作站需優先提供 HTML table 複製格式；純文字備援只能使用 tab 分欄，不可使用 Markdown 表格線。
- SEO/AIO 可作為內部生成檢查，但不顯示給 Kevin，也不放入投稿正文。
- 每篇至少引用 2 個台灣脈絡來源作查核，優先順序為政府、統計、金融機構、法院、可信新聞。
- 凡涉及補助、津貼、計畫、申請資格、金額、期限、法規或政府服務，必須查核目前有效版本。
- 中央與地方政府規範必須分開判讀，不能混寫。
- 若最新版本、適用年度、主管機關或地方差異無法確認，文章不得標示為可投稿。
- 每篇必須對應正式文章專區標籤。
- 每篇必須經過「非概念文檢查 agent」。
- 每篇正文至少要有 2 個具體數值或數值化情境。
- 每篇正文至少要有 1 個前後差異示例。
- 每篇正文必須指出 1 到 3 個改善關鍵因素。
- 示意數字必須標示為假設情境；官方金額、補助、資格、利率、年度與地方規範必須查核最新台灣版本。
- 使用化名情境時，每次新產文章包需先掃描既有 `articles/**` 中的 `＿（化名）`，不得重複使用已出現過的化名；若因延續同一個案例而必須重用，需在內部紀錄 Kevin 的明確要求。
- 預設文章必須從一般民眾的生活壓力、前後差異或具體選擇切入。
- 未經 Kevin 明確指定，不得生成社工版，不得在正文中加入社工評估、介入、陪伴者指令或給作者的寫作建議。
- 正文若出現「這篇文章」「本文可以」「文章最後」「文章發展」「對一般民眾版而言」「如果這篇要投稿」「知識庫文章要」「可以提醒讀者」「建議每篇」等後台語，必須退回重寫。
- 同一批 10 篇標題不得大量使用同一個公式，例如全部寫成「不是＿＿：＿＿」。標題需混合生活場景、具體問題、數字切入、後果提醒、時間壓力或選擇困境。
- 每篇開寫前必須建立 `topicEvidenceCard`，確認題目不是空想；若缺少台灣資料、制度、新聞、知識庫缺口或駁回訊號支撐，不得寫成普遍現象。
- 每篇開寫前必須建立 `readerFitCard`，確認前 150 字有生活矛盾、金錢卡點、時間壓力或家庭選擇困難。
- 每篇開寫前必須建立 `financialDecisionCard`，確認文章能協助讀者做至少一個家庭財務評估。
- 每篇開寫前必須建立 `improvementPlanCard`，確認文章有目前缺口、2 到 3 個可執行調整、調整後效果、剩餘缺口，以及打平或求助判斷。
- 每篇開寫前必須建立 `readerLoadCard`，確認文章只有 1 個主問題、最多 2 個支撐問題、最多 3 個行動與 1 個安全提醒；超出即拆題，不得硬塞成一篇。
- 每篇文章必須讓讀者帶走一個財務知能，例如看現金流、分類支出、比較成本、查證資訊、辨識風險或保留緩衝。
- 每篇文章必須建立 `articleUsefulnessCard`，確認資訊、故事、數字與結尾都服務同一個家庭財務判斷；若文章資訊完整但讀者不知道要先看哪個數字、日期、風險或選擇，必須退回重寫。

## 開寫前議題驗證

假設情境可以使用，但題目本身不能只是 agent 想像出來的問題。

每個題目開寫前，必須先回答：

- 這個問題在台灣真的存在嗎？
- 哪一群家庭可能會遇到？
- 它和家庭收入、支出、債務、照顧成本、補助資源、居住成本或風險承擔有什麼關係？
- 有沒有官方資料、制度公告、可信新聞、知識庫缺口、駁回訊號或可查核生活成本可以支撐？

證據等級：

- 官方事實：政府公告、法規、統計、補助規定。
- 真實案例：可信新聞、公開事件、去識別化且可查核的案例。
- 合理估算：以台灣常見薪資、房租、托育、長照、交通或生活成本推算。
- 假設情境：為了幫讀者理解而設計的家庭情境。

使用規則：

- 官方事實可以支撐制度與資格描述。
- 真實案例只能取關鍵情節，不鋪成戲劇故事。
- 合理估算要保守，且能說明估算邏輯。
- 假設情境只能用來示範，不能當成題目成立的唯一證據。
- 若證據不足，文章需降階為「家庭盤點型」，例如「若你家剛好遇到這種狀況，可以先看哪三件事」，不得寫成「很多家庭都正在發生」。

## 易讀性與閱讀吸引力

一般民眾願不願意讀，通常不是因為文章有沒有道理，而是開頭有沒有先碰到他的生活。

每篇文章需通過：

- 前 150 字檢查：必須出現生活矛盾、金錢卡點、時間壓力或家庭選擇困難。
- 掃讀檢查：段落標題需能讓讀者快速知道本段要重新看懂什麼。
- 節奏檢查：長段資料需拆成生活問題、數字、判斷，不可成為引用堆疊。
- 語氣檢查：不得責備讀者，不用「你應該」「你只要」「你缺乏紀律」。
- 吸引力檢查：前段要讓讀者看見讀下去的理由，例如能知道哪筆錢先看、哪個日期最卡、哪個缺口最急。

不合格訊號：

- 開頭像百科、課程、政策宣導或報告摘要。
- 前三段都沒有家庭角色、金額、日期、缺口或具體選擇。
- 標題和段落很正確，但讀者不知道為什麼要繼續讀。

## 財務評估與財務知能

文章的目標不是替讀者做正式財務判斷，而是讓讀者更能評估自己的處境。

每篇至少要包含一個低門檻財務評估任務，例如：

- 看 30 天必要支出。
- 看固定扣款日與薪水進帳日。
- 算每月缺口。
- 算手上現金可撐幾天。
- 比較申請補助前後差異。
- 比較調整支出前後差異。
- 比較借款、協商、延後或尋求資源的風險。

每篇至少要轉移一個財務知能：

- 看現金流。
- 分類固定支出與可調整支出。
- 比較選項的前後差異。
- 查證政府資源與資格。
- 辨識高風險借款或詐騙。
- 保留緩衝與避免新增債務。

合格文章的讀後效果：

- 讀者不只覺得被理解，也知道自己可以先看哪個數字。
- 讀者不只知道有資源，也知道資源有時間差、資格差或地方差。
- 讀者不只得到建議，也知道該怎麼比較選項。
- 讀者不被推向單一答案，而是能更清楚地做下一步判斷。

## 結構性財務與現金流盤點

現金流文章不能只寫「帳戶有錢但會慌」的感覺，也不能只放一張表就算結構化。

若題目涉及房租、帳單扣款、薪水進帳、補貼入帳、月底不夠、帳戶餘額看起來還有錢等情境，必須通過 `structuralCashflowReview`：

- 收入時間：下一筆確定收入是哪一天、多少錢、是否已確定。
- 固定承諾：房租、房貸、分期、保費、信用卡、家用或托育等不能任意取消的支出。
- 扣款日期：每筆重要支出在哪一天發生，是否卡在薪水前。
- 受保護的錢：已經有用途、不能拿來花的金額。
- 真正可用現金：帳戶餘額扣掉受保護支出與最低生活費後，還剩多少。
- 缺口類型：一次性時間差、每月固定赤字、突發支出造成的短缺，或已經需要正式求助。
- 下一步：先調日期、先守哪筆錢、先查哪個正式管道，或先避免哪種高風險補洞。

合格文章要讓讀者讀完後可以照著盤點自己的家庭，不只是理解作者想說什麼。

不合格訊號：

- 只寫情緒與故事，沒有讓讀者完成收入、支出、日期與缺口盤點。
- 只把「帳戶餘額」「已預留支出」「真正可用錢」寫成概念，沒有算出缺口。
- 表格只是輔助閱讀，沒有導向可行判斷。
- 結尾仍停在「不要只看帳戶餘額」，但沒有留下下一個盤點動作。

## 高變異條件題材

有些題材不是不能寫，而是不能把化名情境當成主要參考。

凡是結果高度依賴個別條件的題材，都要先通過 `highVariationTopicReview`，例如：

- 資遣、失業給付、職災、勞保、就業保險。
- 租金補貼、托育補助、社會救助、地方政府加碼方案。
- 債務協商、保單借款、醫療費、長照服務、自付比例。
- 任何資格、投保薪資、戶籍、所在地、文件、核定時間或契約條款會大幅改變答案的題材。

這類文章的重點應改成「讀者要查哪些變數」，而不是「某個家庭可以怎麼做」。

合格做法：

- 先列出會改變答案的變數，例如資格、日期、金額、文件、所在地、契約、投保薪資、收入證明。
- 把示例數字標示為練習用，不把它當成可套用結論。
- 用決策清單、盤點表、問窗口前的準備表，取代個案式解法。
- 若條件差異太大，降階為「工具／清單／求助前盤點」，不要標示為可投稿故事型文章。

不合格訊號：

- 用一到兩個化名情境代表所有讀者。
- 因個案條件不同會導致完全不同結果，仍寫成可參考方案。
- 情境很完整，但讀者不知道自己要填入哪幾個資料才能判斷。
- 制度細節尚未查核最新版本，卻把文章標示為可投稿。

## 財務風險判斷與解法選擇

故事、數字、表格都只是工具。真正要過稿，文章必須讓讀者看懂自己家的財務風險，並知道下一步要選哪一種處理方法。

每篇涉及家庭收支、醫療、保險、債務、補助、居住、照顧或就業變動的文章，都必須通過 `financialRiskDecisionReview`：

- 風險判斷：讀者能不能分辨自己是短期時間差、每月固定赤字、保障被吃掉、醫療延誤、債務惡化，還是已經需要正式求助。
- 家庭財務後果：這個風險會讓家庭哪一塊出問題，例如房租斷裂、生活費被吃掉、月付變重、保障變薄、理賠變少、照顧者收入下降或新增債務。
- 解法選擇：文章要說清楚哪一種情況適合哪一條路，例如分期、降低借款額度、保留醫療預留金、調整扣款日期、查正式窗口、尋求社福或債務協商。
- 方法可信度：解法必須符合台灣制度、生活常理與家庭限制。不能假裝每個人都敢跟房東談、每個人都有親友能借、每個人靠節省就能打平，也不能把尚未查核的地方方案寫成全台通用。
- 求助分流：如果調整後仍無法打平，要說明先問哪個正式窗口或哪類資料要準備；不能停在「可以尋求協助」。

不合格訊號：

- 文章很有故事感，但讀者不知道自己是哪一種風險。
- 有清單或表格，但只是分類，沒有導向解法選擇。
- 有改善建議，但沒有說明它解決哪一個家庭財務後果。
- 解法在台灣現實中過度牽強，例如把高門檻協商、親友支援或制度資源寫得很容易。
- 最後只剩情緒安慰，沒有留下可判斷的下一步。

## 改善計畫與剩餘缺口

文章若只寫出家庭陷困，卻沒有討論如何往打平靠近，讀者很難拿來參考。

每篇涉及收支、債務、補助、照顧、居住、失業、詐騙或風險的文章，都必須在正文中自然呈現一個可討論的改善計畫。這不是要替讀者做正式財務處方，而是讓讀者看懂：目前缺口在哪裡，做了哪些調整後可能改善多少，還剩多少沒有解決。

`improvementPlanCard` 至少要先填完：

- 目前缺口：必要支出、必繳款、確定收入與已確認資源各是多少。
- 改善行動：最多 2 到 3 個，必須合理、低門檻，且與本文主題直接相關。
- 施行效果：用前後差異說明，例如月缺口從多少降到多少、可撐天數從幾天變幾天、月付壓力下降多少。
- 剩餘缺口：調整後是否能打平；若不能，還差多少或卡在哪個時間點。
- 求助路徑：若無法打平，要寫出具體且合理的詢問方向，例如戶籍地或居住地社會局處、鄉鎮市區公所社會課、社會福利服務中心、1957 福利諮詢專線、債務協商正式管道或該議題的主管機關。涉及政府資源時，上稿前仍要查核最新資格、窗口與地方差異。

剩餘缺口的基本算式：

必要支出 + 必繳款 - 確定收入 - 已確認資源 = 剩餘缺口

若剩餘缺口小於或等於 0，文章要說清楚打平的關鍵是什麼，例如固定支出下降、補助接上、還款月付降低、請假損失減少或支援分工穩定。

若剩餘缺口大於 0，文章不能停在「再努力一點」。必須說明下一步要優先查哪個資源、找哪個承辦窗口、準備哪類資料，或先避免哪一種高風險補洞方式。

不合格訊號：

- 只寫「可以尋求協助」，但沒有說向誰詢問。
- 只寫「調整支出」，但沒有說哪一筆、差多少、能不能打平。
- 只寫補助金額，沒有說補助進來後家庭是否仍有缺口。
- 文章最後仍讓家庭留在赤字，卻沒有求助路徑或風險提醒。

## 讀者負荷與單篇訴求

每篇文章要能被一般民眾消化，不是把所有相關議題一次講完。

`readerLoadCard` 必須檢查：

- 1 個主問題：這篇到底要處理哪個家庭財務卡點。
- 最多 2 個支撐問題：只保留會影響主問題判斷的因素。
- 最多 3 個行動：每個行動都要能對應到一個數字或生活安排。
- 1 個安全提醒：例如避免高利借款、查核官方資訊、不要把不穩定支援算進固定預算。

若文章同時想處理托育、租屋、債務、長照、詐騙、補助、家庭關係與職涯，必須拆題。單篇文章的價值是讓讀者把一件事看清楚，不是讓讀者被更多資訊壓住。

## 標題多樣性

標題的任務不是把文章包整理成系列，而是讓每一篇都有自己的入口。

標題要先讓讀者感覺「這篇可能跟我的生活有關」，再承接家庭財務判斷。
不要把內部工作台語氣直接放到標題，例如整批都寫成「先看＿＿」「要算＿＿」「把＿＿放進表裡」。這些句型可以在正文中出現，但若 10 篇標題排起來像同一張規劃表，就必須重擬。

除非 Kevin 明確要求做成系列，否則每批標題應符合：

- 不使用同一個句型套完 10 篇。
- 每篇需標記一個標題型態，例如生活畫面、照顧衝突、口語疑問、安心提醒、意外成本、時間壓力、反差句、後果提醒、風險提醒。
- 10 篇以上文章包至少使用 6 種標題型態，且不得只靠換名詞製造差異。
- 「不是＿＿：＿＿」這類重新框架句可以使用，但同批最多 1 到 2 篇。
- 至少混合 3 種以上標題型態，例如生活畫面、問題句、數字句、時間壓力、後果句、家庭對話感。
- 標題要能讓人一眼看出這篇的具體困境，不只看出它屬於同一套概念。
- 若標題讀起來像模板產生，必須退回重擬，不得只改個別名詞。
- 標題必須像台灣人自然會說的中文，避免美語直譯、顧問簡報感或過度抽象組合詞。
- 例如「緊急預備金要先回答收入空窗」「家庭要先做的財務止血」「風險也每天靠近」這類語句，即使意思可懂，也應退回改成更生活的說法。

## 標題台灣語氣與去 AI 感

標題和正文一樣要過台灣用語與去 AI 感檢查。標題不能只是概念正確，也要像一般台灣讀者會自然說、自然點進去的話。

每篇標題必須通過 `titleNaturalnessReview`：

- 不使用硬造詞或內部規劃語，例如「房租日」「收入空窗」「財務止血」「承接風險」「正式資源」。
- 不使用看起來像 AI 把概念拼在一起的漂亮句。
- 不把正文檢核任務直接搬到標題，例如「放進表裡看」「先看能不能」「要先算能不能」。
- 優先使用台灣自然說法，例如「繳房租那天」「房租要繳之前」「薪水還沒進來」「帳單快扣款」。
- 若標題的意思可懂，但讀起來不像台灣人日常會說的話，仍須退回重擬。

## 標題語意清楚度

標題不只要自然，還要講得通。讀者只看標題時，應該能立刻知道這篇文章要處理的生活問題、時間差、金額壓力或決策困難。

每篇標題必須通過 `titleSemanticClarityReview`：

- 一眼能懂主詞、事件與壓力來源。
- 不使用聰明但不合邏輯的反差句。
- 不讓讀者需要猜前後文才知道標題在說什麼。
- 不使用「最難等的不是＿＿而是＿＿」這類容易造成語意跳躍的句型，除非後半句真的是一般人會說的等待對象。
- 若標題讀起來有亮點，但讀者可能問「這句到底是什麼意思」，必須退回。

例如「被資遣後最難等的，可能不是工作而是帳單」應退回，因為一般人不會說「等帳單」。但「被資遣後第一個月，房租和帳單常比失業給付先到」雖然清楚，仍偏平鋪直述；「被資遣那個月，房租要繳、帳單要扣，失業給付還沒下來」又像話沒說完。較好的方向是用完整口語問題承接重點，例如「被資遣後，失業給付還沒下來，這個月房租要怎麼辦？」。

## 標題鉤子強度

標題通過語意清楚度後，還要檢查它有沒有讓讀者想點開。

每篇標題必須通過 `titleHookStrengthReview`：

- 不只是把文章主題摘要出來。
- 至少有一個生活畫面、壓力衝突、具體後果或完整口語疑問。
- 能讓讀者感覺「這篇可能在講我遇到的事」。
- 句子要有收束點，不能只是「房租要繳、帳單要扣、給付還沒下來」這類片語並列。
- 不用太聳動，也不要像新聞驚悚標題。
- 若標題清楚但沒有感覺，或像報告小標，必須退回重擬。

合格方向：

- 生活畫面：「第一份薪水還沒入口袋，房租和家用已經在排隊」
- 口語疑問：「明明每月都有繳，債務怎麼還是卡在那裡」
- 壓力衝突：「公司說先減班，帳單卻不會跟著減半」
- 具體後果：「一場住院不只花醫藥費，還會讓薪水少一段」
- 完整問題：「被資遣後，失業給付還沒下來，這個月房租要怎麼辦？」

不合格方向：

- 像報告摘要：「被資遣後第一個月，房租和帳單常比失業給付先到」
- 像內部規劃：「被資遣後先看30天缺口」
- 像 AI 反差句：「失業後最難等的不是工作，而是帳單」
- 像話沒說完：「被資遣那個月，房租要繳、帳單要扣，失業給付還沒下來」

## 台灣語句邏輯與口語校準

標題與正文要定期用台灣資料、新聞標題與一般討論語氣校準，不只用官方詞。

2026-06-12 針對「被資遣／失業給付／房租」題型的 web learning：

- 官方資料常用「非自願離職」「失業認定」「14日內」「核發失業給付」來說明流程。這些詞可做事實底盤，不適合直接當標題語氣。參考：勞動部勞動力發展署失業給付說明。
- 職場文章常用「被資遣怎麼辦」「可以領多少錢」「當下該怎麼辦」這類直接問題。這類句型能讓讀者知道文章會回答什麼。參考：104 職場力資遣常見問題文章。
- 一般討論常出現「房租等費用需繳」「暫時撐一下」「存款也沒說多到可以這樣」等說法。這代表讀者在意的不是制度名稱，而是眼前這個月怎麼撐。參考：PTT Salary、Dcard 心情板、Mobile01 求助討論。

標題修正原則：

- 先用台灣自然說法講眼前壓力：房租要繳、費用要繳、暫時撐一下、先怎麼辦。
- 再補出文章要處理的核心問題：這個月房租要怎麼辦、第一個月缺口怎麼算、給付下來前先守哪幾筆。
- 避免只列三個狀態：A 要繳、B 要扣、C 還沒下來。這類句子雖有畫面，但沒有結論。
- 標題若用問句，必須是讀者真的會問的問題，不是作者替文章硬設的自問自答。

## 標題讀者心聲流程

標題生成不可一次定稿。

每個題目需經過四段：

1. 整理型標題：先確認文章主題、制度或家庭財務問題沒有偏掉。
2. 讀者心聲標題：把整理語改成讀者真的會問、會搜尋、會跟朋友說的話。
3. 台灣口語檢查：去掉翻譯腔、寫作腔、顧問腔、硬造詞和片語並列。
4. 承諾感檢查：讀者看完標題，要知道點進去可以得到哪一種幫助。

每篇標題必須通過 `titleReaderVoiceReview`：

- 像讀者心裡會冒出的問題，不像作者摘要。
- 像台灣讀者會丟進搜尋框的句子。
- 像會跟朋友或家人說的話。
- 問題要完整，不只列出狀態。
- 不用「先怎麼撐」這類偏寫作或偏整理的語氣；能用「要怎麼辦」時，優先用更自然的說法。

快速測試：

- 這句話如果放進 Google 搜尋框，像不像真人會搜？
- 這句話如果傳給朋友，會不會怪？
- 這句話如果是當事人半夜想到的問題，像不像？
- 讀者看標題後，知不知道文章會幫他看哪個缺口？

參考來源：

- https://emps.wda.gov.tw/Internet/Index/labor-benefits.aspx
- https://blog.104.com.tw/what-can-i-deal-with-lay-off/
- https://www.ptt.cc/bbs/Salary/M.1448386533.A.9F5.html
- https://www.dcard.tw/f/mood/p/260739216
- https://www.mobile01.com/topicdetail.php?f=651&t=5791239

## 正文台灣中文語感

正文也要像台灣一般讀者會自然理解的說法。

不是只把英文概念翻成中文，也不是把內部審稿語放進文章裡。

必須避免：

- 「收入空窗」「進帳空窗」
- 「財務止血」
- 「承接風險」「風險承接」
- 「正式資源」「正式窗口」
- 「策略可以是」
- 「家庭修復」
- 「生活被接住」

應改成更生活的說法：

- 「薪水突然少一段」
- 「一段薪水還沒進來的日子」
- 「先讓錢不要再流出去」
- 「遇到變故時還撐不撐得住」
- 「可以查證的協助管道」
- 「可以詢問的承辦單位」
- 「家裡慢慢恢復穩定」

判斷標準不是「意思是否看得懂」，而是讀者會不會覺得這像一個人在理解他的生活。

## Kevin 修稿樣本學習

Kevin 於 2026-06-03 提供一批人工調整後的文章作為參考。

這批參考稿要學的是寫作判斷，不是照抄句子。

可重複使用的規則：

- 第一句先抓生活機制，不先介紹題目。
- 好的開頭會讓讀者立刻知道「原來卡住我的不是單一金額，而是日期、時間、收入、照顧或帳單的排列」。
- 政策數字不能只是引用，要翻成生活用途，例如兩週通勤、一次診所自費、幾天房租緩衝、少一次刷卡補洞。
- 假設情境要把收入、固定支出、日期和缺口放在同一張生活表裡。
- 前後差異要寫出改善關鍵，不只寫多出多少錢。
- 可以使用短列點整理三個卡點、三個數字或三個順序，但列點後要回到家庭生活壓力。
- 結尾要回到生活選擇與可呼吸的空間，不收在口號或雞湯。

退修訊號：

- 開頭像百科或課程導言。
- 數字像資料堆疊，沒有變成生活判斷。
- 只寫「可以先盤點」，沒有說清楚要盤點日期、金額、順序、限制或取捨。
- 段落都正確，但沒有讓讀者感覺這就是自己的生活。
- 正文出現「示意前後差異」「示意看前後差異」這類寫給作者看的轉場語。
- 結尾只是重述全文、抽象鼓勵或漂亮話，沒有把文章收回生活選擇。

## 通過稿作者結構學習

Kevin 指定可優先參考投稿者：劉泰一、李婉仙、蔡思樂。

這個學習只做結構判讀，不做文字仿寫。有效樣本必須同時符合：

- 來源在「好理家在文章管理區」事件列表。
- 「客戶‑個人」欄位等於劉泰一、李婉仙或蔡思樂本人。
- 審核狀態為審核成功或已定稿可上架。
- 可讀到完整文章或可投稿正文。

不得納入正式學習樣本：

- FB 短文、社群貼文、導流摘要。
- 只有「全文詳見」但尚未讀到全文的評論。
- 事件標題提到作者姓名，但「客戶‑個人」不是該作者本人。
- 無法確認審核通過狀態的文章。

每篇有效樣本只產生 `approvedAuthorStructureCard`：

- 作者名稱。
- 事件來源類型。
- 文章主題與標籤。
- 開頭如何建立讀者入口。
- 段落如何展開問題。
- 數字、案例或制度如何服務文章。
- 是否有改善計畫、施行效果、剩餘缺口或求助路徑。
- 結尾如何收束。
- 可轉成下次生成 gate 的規則。

`approvedAuthorStructureCard` 不保存全文、不保存私有審核原文、不保存可識別事件 ID，也不得在公開戰情室顯示作者樣本文字。

2026-06-11 起，文章生成時必須把三張卡轉成 `approvedAuthorStructureUse`：

- `case_before_after_difference`：學劉泰一樣本的前後差異與改善關鍵。正文要能看出調整前壓力、調整後結果，以及仍有缺口時的下一步。
- `policy_decision_order`：學李婉仙樣本的制度判斷順序。正文要先拆資格、金額、時間差、文件、地方差異，再回到家庭現金流。
- `support_and_risk_layering`：學蔡思樂樣本的風險與支撐分層。正文要分清家庭自有資源、制度資源、親友支持、正式求助與仍未補上的風險。

每篇文章需指定 `primaryPattern`，但三種結構都要被納入生成約束。這是內部生成規則，不得在正文寫成「本文採用某某作者結構」或「對一般民眾版而言」。

## 可見轉場語規範

「前後差異」是內部寫作要求，不一定要成為正文語句。

正文不應出現：

- 示意前後差異。
- 示意看前後差異。
- 示意前後差異會讓人更清楚。

應改成讀者自然會接受的轉場：

- 把調整前後攤開看。
- 把每月結餘拆開看。
- 把時間差算進去。
- 把照顧費和醫療費攤開。
- 讓討論少一點責備，可以先把調整前後攤開。

## 結尾強度

結尾不是把文章結束而已。

好的結尾要做到三件事：

- 回扣開頭的生活矛盾。
- 收成一個清楚判斷。
- 讓讀者知道下一步要先看哪個缺口。

結尾不可只寫：

- 壓力會慢慢變好。
- 重新站穩就有希望。
- 真正重要的是理解自己。

除非這些句子前面已經講清楚：要整理哪個日期、哪筆金額、哪個順序、哪段支出缺口，或哪個支持來源。

## 文章應有的內容層次

一般民眾版：

- 開頭先進入生活矛盾，不先講制度背景。
- 讓讀者感覺被理解，而不是被指導。
- 從表面問題走到生活條件與壓力結構。
- 資料只放在能幫助讀者重新理解處境的位置。
- 結尾回到「重新理解自己與生活選擇」。

社工版只在 Kevin 明確指定時使用：

- 從實務現場常見誤判切入。
- 說明表面現象背後的結構、風險與支持系統。
- 帶出評估、盤點、提問、轉譯與介入焦點。
- 案例與資料服務於判讀，不取代專業分析。
- 結尾收束成清楚的實務立場。

## 非概念文標準

文章若出現下列情形，必須退修：

- 抽象詞很多，但沒有具體生活場景。
- 只說「建立安全感」「提升韌性」「做好規劃」，沒有說明人為什麼做不到。
- 只列資源或制度，沒有寫出它如何影響日常選擇。
- 只列建議，沒有讓讀者看懂壓力來源。
- 資料像引用摘要，沒有融入敘事。
- 文章像 AI 報告，缺少人的處境、情緒與判斷。

每篇文章至少要回答：

- 這篇的具體生活畫面是什麼？
- 讀者會在哪裡卡住？
- 這個卡住和台灣制度、家庭條件或工作收入有什麼關係？
- 哪一個資料或案例真的改變了讀者對問題的理解？
- 讀完後，讀者知道下一步要先看什麼嗎？

## 角色一致與正文純度

讀者看到的正文，只能像一篇已完成的文章。

不能讓讀者看到 agent、作者、編輯或審稿者留下的痕跡。凡是「這篇文章應該怎麼寫」「文章最後可以提醒」「對一般民眾版本來說」這類語句，都不是正文，而是內部建議外洩。

角色一致的標準是：

- 正文只對一般民眾說話，不對作者、編輯、agent 或審稿者說話。
- 預設不對社工、助人工作者或陪伴者下指令。
- 文章不評論自己是什麼版本，也不提投稿、知識庫、審稿或生成流程。
- 所有修稿建議、SEO/AIO、來源清單、gate 自評與 agent 討論都放在內部欄位。

## 數值化證明與書寫角度

數值不是為了讓文章看起來專業，而是為了讓讀者看見差異。

每篇文章應先判斷：這個主題最需要讀者看見哪一種差異。可能是每月結餘差異、固定支出占比、債務月付壓力、補助申請前後、週轉天數、照顧成本或風險緩衝。

合格寫法要能呈現：

- 一個生活或實務現場的起點。
- 一組可理解的數值或情境試算。
- 一個前後差異，例如收入進帳前後、調整支出前後、申請資源前後、債務重整前後。
- 一到三個真正造成改善的關鍵因素，例如固定支出、利息、還款順序、補助資格、照顧成本、收入穩定性或家庭分工。
- 數字後面要說明這代表什麼生活影響或實務判讀。

一般民眾版要從「我為什麼會卡住」進入，不從「你應該怎麼做」進入。避免使用「你應該學會理財」「多記帳就能解決」「問題在於缺乏紀律」「不要亂花錢」「窮人思維」。

社工版只有在 Kevin 明確指定時才生成。若指定社工版，要從「如何判讀服務對象的困境」進入，不從「如何教服務對象改變」進入。避免使用「服務對象缺乏金錢管理能力」「個案抗拒改變」「只要建立正確觀念即可」「應教育個案」「本方案能有效解決」。

若文章只有官方資料，沒有前後差異；只有建議，沒有改善關鍵；或把示意數字寫成真實案例，必須退修。

## 資料與案例使用

資料要支撐文章，不要壓過文章。

寫作時應遵守：

- 每篇正文最多突出 1 到 2 個關鍵數據。
- 來源連結、查核日期與完整資料清單保留在內部審核紀錄。
- 新聞案例只能取可查核的情節，不可改寫成過度戲劇化故事。
- 若是綜合情境，必須明確標示為綜合整理。
- 資料出現後要立刻回到生活影響或社工判讀。
- 如果資料只是裝飾，刪掉。

## 每週 10 篇主題配比

- 生活壓力型：4 篇，例如租屋、單親、青年、預備金。
- 資源制度型：3 篇，例如補助、債務協商、社會救助。
- 風險預防型：2 篇，例如詐騙、高齡風險。
- 家庭經濟轉譯型：1 篇以上，例如收入中斷、長照、資源取得障礙。預設仍寫給一般民眾；只有 Kevin 明確指定時才改社工版。

## Agent 討論流程

每篇文章至少經過下列角色檢查：

- `source_scout`：找台灣官方資料、統計、可信新聞或案例。
- `topic_evidence_reviewer`：開寫前驗證題目是否有台灣現實支撐，避免假設性議題被寫成普遍現象。
- `reader_motivation_reviewer`：檢查前 150 字是否有生活入口，讀者是否有理由繼續讀。
- `financial_decision_reviewer`：檢查文章是否能協助讀者盤點收支、缺口、風險、選項或可撐時間。
- `financial_literacy_transfer_reviewer`：檢查文章是否讓讀者帶走一個可重複使用的財務知能。
- `structural_cashflow_reviewer`：遇到房租、扣款、薪水進帳、補貼入帳或月底不夠題材時，檢查正文是否完成收入時間、固定承諾、扣款日、受保護金額、真正可用現金、缺口類型與下一步盤點。
- `high_variation_topic_reviewer`：遇到資遣、失業給付、補助資格、債務條件、長照自付或地方方案等高變異題材時，檢查文章是否改成變數盤點、決策清單或工具型內容；若仍以個案情境作為主要參考，必須退回。
- `improvement_plan_reviewer`：檢查文章是否有可討論的改善計畫、施行效果、剩餘缺口，以及打平或求助路徑。
- `reader_load_reviewer`：檢查單篇文章是否只處理一個主問題，讀者是否能消化。
- `approved_author_structure_reviewer`：只在已取得有效通過稿樣本時啟用，檢查是否學到通過稿結構，而不是模仿 FB 短文或作者語句。
- `review_feedback_miner`：讀退修/駁回建議，萃取本週必避規則。
- `review_contrast_miner`：把評論中的文章、審核評語、原稿問題段落與通過稿特徵交叉對照。
- `tag_mapper`：對應文章專區正式標籤。
- `article_pattern_miner`：比對已學成功與退修樣本，避免風格錯位。
- `public_writer`：預設依一般民眾版寫稿。
- `social_work_writer`：只有 Kevin 明確指定社工版時才啟用。
- `fact_case_reviewer`：檢查資料年份、數字、政策、案例是否可查。
- `numeric_proof_reviewer`：檢查文章是否有具體數值、前後差異、改善關鍵，且區分查核數字與示意試算。
- `writing_angle_reviewer`：檢查一般民眾版切入角度是否正確，是否出現責備、教訓或錯位語句；社工版只在 Kevin 明確指定時檢查。
- `role_leak_reviewer`：檢查正文是否混入作者建議、審稿語、讀者版本語、投稿語、知識庫語或社工語氣錯位。
- `non_concept_reviewer`：檢查是否太概念、引用感是否過重、AI感是否太強。
- `reader_appeal_reviewer`：檢查前 150 字是否吸引讀者、段落是否有生活畫面、是否像人寫給人看。
- `quality_reviewer`：判定可投稿、退修或駁回。

## 工作台顯示欄位

文章工作站是 copy-only 工具，不是提交、核准或退修系統。每篇文章在工作站的主要任務是讓 Kevin 快速選文章、檢視正文、複製標題＋正文。

每篇文章在工作站只需要優先顯示：

- 標題。
- 讀者版本。預設為一般民眾。
- 正文字符數。
- 正式主要標籤與次要標籤。
- 純文字正文。
- 複製標題＋正文。
- 複製正文。

生成端的品質 gate、來源查核、成功稿學習、駁回對照學習、agent 討論與 role leak 檢查可以保留在 metadata 或折疊區，供回查與 validator 使用，但不應變成工作站的主要操作。

工作站不得提供：

- 核准投稿。
- 退修。
- 駁回。
- 本機審核意見儲存。
- 依本機核准狀態匯出文章包。
- 複製含內部標籤、審稿語或 agent 討論的審稿版。

不顯示：

- SEO Title。
- Meta Description。
- Slug。
- AIO 摘要。
- FAQ。
- 來源清單。

## 文章管理區成功與駁回對照學習

文章生成端必須持續參考「好理家在文章管理區」事件列表，不從文章工作站本機狀態學習。學習來源分成兩類：

- 審核成功事件：讀取可確認為審核成功、可讀到完整文章內文、且來源角色正確的文章，萃取生活入口、段落推進、制度/數字放置、改善計畫與結尾收束。
- 審核駁回事件：讀取駁回內容，並對照原本文章內文，找出被駁回的段落形狀、缺少的證據、讀者負荷、AI 感、角色錯位、數字不足或行動不切實際之處。

每次取得新的審核成功或審核駁回資料時，必須建立或更新學習卡：

- 原文章標題。
- 原稿問題段落。
- 審核成功或駁回內容摘要。
- 問題類型。
- 可檢查規則。
- 修正方向。
- 成功稿可學的結構，或駁回稿需要避開的寫法。
- 是否升級為下週必查門檻。

同類型問題出現 2 次以上，下一輪投稿文章包必須先套用該規則。

若能取得 InfoCenter 事件中的評論文章與審核評語，必須建立 `review_contrast_card`：

- 評論中的文章摘要。
- 審核或駁回評語摘要。
- 原稿問題段落。
- 通過稿是否有相反特徵。
- reviewer agent 討論摘要。
- 可檢查規則與修正示範。
- 是否升級為下週必查門檻。

目前已完成「文章正文＋審核狀態」的群體學習；若尚未取得評語原文，不可宣稱已完成逐則交叉對照。

## 學習資料庫累積

每次文章生成、退修或駁回後，至少保留這些可回查欄位：

- 文章基本資料：標題、讀者版本、主要標籤、次要標籤、審核狀態、修訂次數。
- 書寫角度：切入角度、首段類型、核心重新框架句、主要情緒、讀者會帶走的問題。
- 議題驗證：題目證據來源、證據等級、台灣相關性、家庭經濟關聯、是否降階為家庭盤點型。
- 讀者吸引力：前 150 字入口、讀者痛點、段落掃讀、是否有繼續閱讀理由。
- 文章有用性：文章只推動的一個家庭財務判斷、要避免的常見誤判、讀者讀完後要先檢查的數字/日期/風險/選擇。
- 財務決策幫助：讀者要先看的數字、日期、支出、缺口、風險或選項比較。
- 財務知能轉移：讀者可重複使用的能力，例如看現金流、分類支出、比較成本、查證資訊、辨識風險或保留緩衝。
- 改善計畫：目前缺口、改善行動、施行效果、剩餘缺口、是否打平、若未打平的求助路徑。
- 讀者負荷：主問題、支撐問題、行動數、安全提醒、是否需要拆題。
- 通過稿結構學習：只保存去識別結構卡，且排除 FB 短文、社群導流與客戶‑個人不符的事件。
- 數值化證明：數值類型、數值文字、來源類型、來源年度、是否最新台灣資料、前後差異、改善關鍵、是否為假設情境。
- 非概念文檢查：是否有生活畫面、具體支出、前後差異、決策困難、家庭或關係壓力、服務現場、下一步判讀。
- 語氣與禁用語：原句、風險類型、建議改寫、適用讀者版本。
- 退修學習卡：審核意見、問題類型、可檢查規則、修正後片段、是否升級為下週必查門檻。
- 交叉對照卡：event_id、article_id、評論文章摘要、審核評語摘要、原稿問題段落、通過稿對照、agent 討論、升級規則。

- 帳務核對型：用收入、固定支出、前後差異揭露問題。

## 2026-06-15 補充：文章有用性與工作站邊界

`articleUsefulnessReview` 是生成端 gate，不是工作站按鈕。

每篇文章都必須先回答：

- 這篇只要讓讀者更會判斷哪一件家庭財務問題？
- 讀者最容易把這件事誤會成什麼？
- 正文中哪一段生活情境或前後數字，會讓讀者看懂差異？
- 讀者讀完後，要先檢查哪一個數字、日期、風險或選擇？
- 這篇是否把多個議題塞在一起？如果是，先拆題，不靠段落補充硬塞。

生成後的文章工作站只負責把可用內容交到 Kevin 手上：選文章、看正文、複製標題＋正文。工作站不保存核准、退修、駁回，不作為文章管理區的替代審核流程，也不把本機操作寫回 InfoCenter。

語氣變奏規則：

- `不是...而是 / 而在 / 而要 / 只是` 單篇最多 3 次。
- 整包總量不得超過文章篇數。
- 使用這類對比公式的文章不得超過整包一半。
- 不得出現 `怎麼做比較穩`、`比較穩的做法`、`比較穩的順序`、`比較穩的是`、`比較穩，`。
- 擋下假自問自答轉場，例如 `但這個月五號怎麼辦，還是要先處理`。
- `真正` 單篇最多 3 次。

這些規則是用來要求重寫，不是用來做表面同義詞替換。若句型過量，應回到段落目的與生活語氣重寫。
