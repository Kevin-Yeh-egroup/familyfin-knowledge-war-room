# 2026-06-03 審核駁回點擊學習批次

## 任務定位

本批次的目的不是只統計「審核駁回」狀態，而是實際點進 InfoCenter 事件列表中的審核駁回列，讀取審核明細，再與評論中的文章本文交叉對照。

這次確認了一個重要規則：

**只看審核標題不夠。**

審核標題可以判斷退稿類型，但真正能讓 agent 學會文章品質標準的是審核內容。審核內容通常會說明為什麼文章不夠具體、哪裡與現實不符、哪些財務數字或風險沒有被寫出來。

## 完整學習卡標準

一筆審核駁回事件只有在同時具備以下三者時，才算完整學習卡：

1. 評論中的文章本文已打開
2. 審核標題已讀取
3. 審核內容已讀取

只有審核標題、沒有審核內容時，只能算部分訊號。它可以提醒 agent 某類問題曾出現，但不能單獨作為改寫規則的主要依據。

## 已形成的學習方向

本批次完整學習卡主要指向三類品質門檻：

- 案例與數字必須一致：家庭人數、角色、收入、支出與費用不能前後矛盾。
- 財務數字必須可驗證：收支、補助、托育費、租金、工資與改善前後差異都要有來源或合理假設。
- 文章不能只停在概念：若提到工具、行動或介入，要說清楚它如何改變財務數字，以及未來風險如何降低或仍需追蹤。

## 對 agent 的新門檻

後續產生可投稿文章時，reviewer agent 必須新增以下檢查：

- `review_feedback_miner`：不得只讀審核標題，必須讀審核內容。
- `numeric_proof_reviewer`：檢查每個財務數字是否有來源、假設或前後差異。
- `non_concept_reviewer`：檢查每段是否有具體情境、數值變化或行動後結果。
- `writing_angle_reviewer`：檢查文章是否符合好理家在知識庫的財商教育與助人工作定位。

## 後續建議

下一批應優先回查仍未形成完整學習卡的審核駁回事件，並把「只有標題」與「有內容」分開統計。週五流程應把審核內容讀取率列為品質指標，而不是只回報點擊成功率。
